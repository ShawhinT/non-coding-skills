Read this file when you need to audit a claim in SKILL.md, settle an edge case

replies. It is not needed for ordinary drafting.

## Provenance

- **Source:** YouTube Studio "Responded" comment inbox, account `@ShawhinTalebi`
- **Sample:** 111 replies
- **Window:** February–August 2026
- **Method:** every reply in the window read and coded by hand; percentages are
  counts over the full 111, not a subsample

Everything in SKILL.md traces to this sample. Where a rule generalizes past it
— to LinkedIn, X, Substack, Instagram — that is a deliberate call by Shaw, not
a measured finding. The register held constant enough across comment types
within YouTube that treating it as a comment-reply register rather than a
YouTube register was the judgment made when the skill was built.

## Measurements

| Signal | Value |
|---|---|
| Median reply length | **17 words** |
| Mean reply length | 25 words |
| Replies ≤15 words | **47%** (52 of 111) |
| Replies >60 words | 9% (10 of 111) |
| Open by validating the comment ("Good question!") | **33%** |
| Contain `:)` | 20% |
| Contain an emoji | **0%** |
| Contain an exclamation point | 64% |
| Contain a link | 23% |
| Contain "I" | 34% |
| Contain a hedge (*I think / I don't think / maybe / probably*) | 14% |
| End with a question back to the commenter | 3% |
| Contain "LOL" | 5% |
| Use `e.g.` or `i.e.` inline | 13% |
| Use "I don't think X" specifically | 12 replies |

## How to read the numbers

**Median vs. mean matters more than either alone.** A 17-word median against a
25-word mean means the distribution is short with a long tail — most replies
are very short, and a handful of multi-part technical answers drag the average
up. Writing to the mean produces replies that are too long roughly half the
time. Write to the median and let the multi-part questions pull you up.

**The 0% emoji figure is the load-bearing one.** It is the only signal in the
table with no exceptions across 111 samples, which makes it the most reliable
tell. A drafted reply containing an emoji is wrong regardless of how well the
rest of it reads. Note that this is specific to *replies* — Shaw's own
long-form Community posts do use emoji, so the contrast is a register
distinction, not a personal aversion.

**64% exclamation points alongside a 17-word median** is what keeps the voice
from reading as curt. The brevity would be cold without them. They cluster in
the opener and the thanks, almost never in the substance — so the pattern is
warm framing around a flat, direct answer, not warmth distributed evenly.

**3% end with a question back.** This is worth noticing because a lot of
generic "engagement" advice recommends the opposite. Shaw closes the loop
instead of reopening it.

## Extending the profile

If a new batch of replies gets pulled — from another platform, or a later
YouTube window — the useful move is to recompute the table above on the new
sample and compare, rather than appending impressions.

The three signals worth checking first, because they'd change how the skill
drafts:

1. **Emoji rate.** If a platform's replies use emoji, that's the biggest
   divergence and SKILL.md's "avoid" list needs a platform carve-out.
2. **Median length.** A different median means the routing table's targets need
   rescaling for that platform.
3. **Validation-opener rate.** If "Good question!" is rarer elsewhere, the
   ≤3-word validation stops being the default opener.

Everything else — the concede-first move, hostility handling, links-are-earned
— is stance rather than mechanics, and is likely to hold across platforms even
if the surface numbers shift.
