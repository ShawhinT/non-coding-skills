# Referral Track — Ask & Names

Statuses touched: Referral Status `Not Asked` → `Asked` (names arriving stay `Asked` — the
ledger records them; the next flip is `Intro Made`). Sequence policy
(check-in on-ramp vs. straight ask, cadence, templates) lives in the Referral Ask SOP.

## 1. Open the referral track

**Trigger:** the scheduled on-ramp date arrives (set at review greenlight), a high-goodwill
moment per the SOP (wrap-up call, named win), a client offers referrals unprompted, or Shaw
says "kick off a referral ask for X".

Most people already have a row (the review track created it). Referral-first cases (offered
referral with no training, coffee-chat contacts) may need a fresh row: create it per
`testimonial-ask.md` §1 mechanics, Review Status `Not Asked`, and note why the review track
is skipped.

1. On the row: add the `## Referrals` body header if absent (context above it, ledger lines
   below). Notes get a `Referral track:` prefix on the first referral event so the log reads
   cleanly per track.
2. Note in Notes whether the referral was *offered* (they volunteered — skip the on-ramp,
   go straight to the ask) or a *general ask* (open with the check-in on-ramp). This decides
   where the sequence starts, not the cadence.
3. **Hand off to `email-helper`** for the right touch per the SOP. The on-ramp starts a
   fresh "Checking in" thread — never a reply onto the testimonial thread.
4. **After the ask:** the check-in is not the ask — log it in Notes, update Last
   Contact, Referral Status stays `Not Asked`. Flip to `Asked` only when the actual referral
   ask goes out. Next Contact per the SOP cadence either way.
5. **Touch ownership:** if the row wasn't already owning the person's next touch (referral-
   first cases), take it now — clear the CRM record's Next Contact, add the pointer
   (`testimonial-ask.md` §1 step 6).

## 2. Log names

**Trigger:** the referrer replies with names, mentions people on a call, or Shaw relays them.

1. Referral Status stays `Asked` — the ledger line below is the record, and the ball is
   still with the referrer until an intro exists. Last Contact = the date the names arrived.
2. One ledger line per person under `## Referrals`: name, title/company if known,
   `named M/D`.
3. **Hand off to `email-helper`** for the next move per the SOP — draft the intro for them
   to forward, or share the forwardable script (which the *referrer* sends, never Shaw).
4. Next Contact: keep the post-ask FU cadence running until the intro lands — an ask with
   names but no intro is still open, and when the referrer is sending the note themselves
   there is otherwise nothing scheduled to catch it stalling. Clear only on a terminal
   outcome; the +2-wk clock starts at `Intro Made` (per the SOP).
